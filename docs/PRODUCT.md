# Putio Manager product context

## Register

product

## Users and purpose

People manage their put.io downloads through a desktop client or a separate download server. The application makes the current host, account connection, delivery progress, verification and cleanup state understandable. A Remote client controls the server without downloading media to the client computer.

## Product priorities

- Preserve credentials, settings, job history, pause/cancel intent and existing media across installation and updates.
- Explain failures with short, direct sentences and a concrete next action.
- Keep agents on the CLI with allowlisted operational output and anonymous references.
- Make account, filesystem and software changes deliberate and verifiable.
- Use generated data in demonstrations and public documentation.

## Interface character

Use the existing compact charcoal interface, yellow primary actions, Roboto typography, familiar buttons and bundled Heroicons. Retain the existing spacing, keyboard focus, responsive navigation and Copy controls. This work adds an Updates section, not a visual redesign.

## Avoid

Do not mix desktop software updates with Remote server updates. Do not expose credentials, machine paths, media names or raw diagnostics in update status. Do not claim installation succeeded before the installed version is verified.

## Accessibility

Use ordinary labeled controls, visible keyboard focus, live status announcements and bounded progress. Keep actions usable at the existing default and narrow window sizes. Respect reduced motion and avoid relying on color alone.
